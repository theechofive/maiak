# Phase 2: self-service tenants, plans, watchdog, admin panel

Decisions: [ADR-0092](../adr/0092-self-service-tenants-plans-admin.md). Conventions as in [README.md](README.md): one commit per task, independent review before the next task, ledger entries for shortcuts.

| ID | Task | Depends on | Status |
|---|---|---|---|
| P-01 | **Plans and quotas.** Migration: `plans` (global, seeded `free` and `internal`), `tenants.plan_key` (existing `default` tenant becomes `internal`), definer-free reads of the plan for the tenant. Quota resolution = plan limits overridden by `tenants.limits`. Enforce on the server: monitor count (replaces the hard-coded 50), later heartbeat count and channel count (the Slack channel is limited to 1). `GET /api/v1/usage` returns plan, limits and current usage. Clear 409 problem `plan_limit_reached` with the limit name. Web: plan and usage on the Settings page, friendly message and disabled Add button at the limit. Tests incl. concurrent creates at the limit (reuse the tenant row lock). | none | done |
| P-02 | **Registration (no email).** `POST /api/v1/auth/register` (email, password; email normalised and unique, password policy: at least 12 characters and a length cap; argon2id), creates the tenant (generated slug, name from the email domain) on `free`, the user as `owner`, and a session. Kill switch `MAIAK_REGISTRATION_ENABLED` (chart value, default true). Login accepts an email or the system login `admin`; fix `users.email` constraints for real emails (closes L-160, R-120). Per-IP limit reuses the existing in-memory limiter (known per-replica limit). Web: Register page and links between Login and Register. Audit rows. Tests incl. duplicate email (generic message), password policy, kill switch, tenant isolation between two registered tenants. | P-01 | done |
| P-03 | **Heartbeat monitor (watchdog).** Monitor type `heartbeat` with `expectedIntervalSeconds` (default 300, 60 to 86400) and `graceSeconds` (default 60). Token: 32 random bytes, URL-safe, stored as a hash, shown once at creation, regenerate endpoint. Public `GET|POST /api/v1/heartbeat/{token}` (routed by the existing `/api` rule; no session, constant-time lookup by hash, always the same cheap answer for unknown tokens, simple rate limit), recorded as a ping. A `jobs` task marks overdue heartbeats as failures (`heartbeat_missed`) through the incident machine; a ping resolves. Counts against the heartbeat quota. Web: create form, details page with the one-time URL, last ping, an Alertmanager `Watchdog` receiver snippet. Docs: example Alertmanager config. Tests incl. missed interval, recovery, replayed and unknown tokens, quota, pause. | P-01 | done |
| P-04 | **Platform admin panel.** `users.is_platform_admin` (the system `admin` gets it). Admin API under `/api/v1/admin`: list and get tenants (plan, usage, user count, created, status), change plan, suspend and unsuspend, soft delete, list users, reset a user's password (temporary password shown once). Definer functions check the flag inside and are on the schema-lint allow-list. Web: `/admin` area visible only to platform admins (tenant list and detail). Audit rows for every action. A suspended tenant cannot log in, its monitors are not claimed. Tests incl. non-admin gets 403, cross-tenant isolation unchanged for normal users. | P-01, P-02 | todo |

Ledger: add the M1 scenario as a risk and close it when fixed. | P-03 | todo |
| P-08 | **Fixes from the review of P-03.** (M1) the per-IP limit must apply ONLY to unknown tokens: check the per-token limit first, look the token up, never let unknown-token traffic from an IP (or the shared bucket used when the IP cannot be determined) block valid pings; keep a small bounded cache of recently accepted hashes; (m2) reject tokens that are not exactly 43 base64url characters with the same 404 BEFORE reading the body and before any database work, and bound concurrent in-flight pings; (m3) the heartbeat config CHECK requires integer-shaped `graceSeconds` and `expectedIntervalSeconds` (text pattern) so the casts in `list_due_heartbeats` can never fail (new forward-only migration, also validate existing rows); (m4) `heartbeat_ping` sets `last_ping_at = greatest(last_ping_at, clock_timestamp())`, new function body with the same signature; (m5) lower the L-202 trigger or skip `ApplyResult` for pings when the state is already up (only bump `applied_ping_at`); (m6) the web Alertmanager snippet matches the runbook (root `receiver`, `max_alerts`), the secret command uses an explicit `--context` placeholder and `--from-file=url=/dev/stdin` instead of putting the URL on the command line. New tests: a valid token pinged from an IP whose unknown-token budget is exhausted still gets 204, malformed token never touches the database, ping time ordering vs the evaluation lock, CHECK rejects `60.0`. | P-03 | todo |
