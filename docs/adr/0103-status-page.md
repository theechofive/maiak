# ADR-0103: Public status page

- Status: Accepted
- Date: 2026-11-05

## Context
Client 2 wants a public page that shows the health of its services (P-05, deferred since L-004). The incident model was prepared for it (`incident_monitors`, L-092). The page is the first surface that unauthenticated visitors read from tenant data, so what it shows must be a strict projection and its load must not reach the dashboard's database paths. Roles come from ADR-0102.

## Decision
- **Ownership.** A status page belongs to the organization (tenant), not to a project. One page per organization at first (plan limit `max_status_pages`, 1 for every plan); the schema allows several (L-270). Only owners and admins configure it (ADR-0102); other members see the public link.
- **Content.** The admin picks monitors and heartbeats from any project and turns each into a **component** with a public name (1-60) and an optional group name; order is explicit. Internal monitor names, URLs, error kinds, latency and project names are never published.
- **Status.** Component: `operational` (up), `degraded` (failing checks below the failure threshold, or some locations down once there are several), `outage` (down), `no_data` (unknown or paused, excluded from the overall status). Overall: `operational` when every component is operational, `degraded` when the worst is degraded, `partial_outage` when some but not all components are in outage, `major_outage` when all are.
- **History.** 90 daily bars per component (uptime from the hourly rollups, `no_data` for days without checks). Heartbeats have no rollups (L-201): their bars come from incident durations (L-275). Incidents are shown automatically, only for selected monitors: generated public title ("{component} is unavailable"), affected components, start and resolve times. Past incidents of the last 90 days. Manual updates and maintenance notices come later (`incident_updates`, L-267).
- **Data path.**
  - Tables (module `statuspages`, forced RLS, composite keys): `status_pages` (`tenant_id`, `id`, `slug`, `title`, `logo_url`, `accent_color`, `password_hash` nullable, `published`, timestamps, `deleted_at`), `status_page_components` (`tenant_id`, `id`, `page_id`, `monitor_id`, `public_name`, `group_name`, `position`), and `status_page_snapshots` (PK `page_id`, `slug`, `payload jsonb`, `etag`, `generated_at`), the prepared public view.
  - A `jobs` housekeeping task rebuilds the snapshot of every published page every 30 s and right after a configuration change, through a definer function that writes only the allow-listed fields. The builder is the only code that decides what is public; a golden test asserts the exact JSON keys.
  - Deleting a monitor removes its component; a page with no components shows "No components".
- **Renderer.** A new process `statuspage` (`cmd/statuspage`, same image) serves `/status/<slug>`, `/status/<slug>.json`, `/status/<slug>/feed.rss` and `/status/<slug>/badge`. It has no sessions and reads only `status_page_snapshot(slug)`, a definer function, as a new runtime role `maiak_statuspage` with `EXECUTE` on that function and nothing else (created by `maiakctl db bootstrap`, never by migrations). Server-rendered `html/template` (everything escaped, no user HTML), styles built from the design system tokens, colour scheme from `prefers-color-scheme`, English only (L-272). Caching: in-process cache per slug (15 s), `ETag`, `Cache-Control: public, max-age=30`; per-IP rate limits per replica (L-274). The gateway routes `/status` to it on the internal domain first; custom domains (CNAME and certificates) wait for the public-domain move (L-266).
- **Slug.** Chosen by the admin, globally unique, pattern `^[a-z0-9][a-z0-9-]{2,62}$`, reserved words (`api`, `admin`, `status`, `login`, `register`, `assets`, `static`, `health`, `metrics` and similar) refused. A slug is not a secret; an unpublished page answers 404 like an unknown one.
- **Password.** Optional, argon2id hash, at least 12 characters. A correct password sets an HMAC-signed cookie scoped to `/status/<slug>` (key from the generated secrets, ADR-0091); attempts are rate limited per IP. A protected page serves no JSON, RSS or badge and is sent with `Cache-Control: private, no-store`.
- **Branding.** Title, logo URL (`https` only, at most 500 characters, shown with `<img>` and `referrerpolicy=no-referrer`, never fetched by the server) and accent colour (`^#[0-9a-f]{6}$`, applied through a nonce'd style element). The status colours follow the design system, so the accent cannot fake a red "down" block.
- **Security headers.** `Content-Security-Policy: default-src 'none'; style-src 'self' 'nonce-...'; img-src 'self' https:; frame-ancestors 'none'; base-uri 'none'; form-action 'self'` (the badge allows `frame-ancestors *`), `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`. SSRF does not apply (no outbound calls).
- **Feeds and embedding.** RSS 2.0 of incidents (opened and resolved). The badge is a small HTML page for an `<iframe>` ("All systems operational" or the overall state, linking to the page); `/status/<slug>/embed.js` inserts that iframe. The JSON has the overall status, components with their state and bars, and incidents. No email or webhook subscriptions yet (L-268).
- **Audit:** `status_page.created`, `status_page.updated` (field names only), `status_page.published`, `status_page.unpublished`, `status_page.deleted`.

## Consequences
- One more process and database role; the public surface never touches the api's role or sessions, and a renderer bug can only leak what the snapshot already holds.
- Public state lags up to about 45 s (snapshot plus cache). Acceptable for a status page; the dashboard stays live.
- An admin can publish a misleading name or an overly broad selection; the projection limits the damage to public names and up/down history (R-211).
- Supersedes the "subdomain + CDN" idea of L-004 for the first version; L-004 is closed when P-05 is done.

## Implementation notes (P-05, 2026-11-06)
Choices made while building P-05 within this decision:
- **Migration** `20261106120000_status_pages.sql` (expand only). The reserved slugs are a `CHECK` in the table and `statuspages.ReservedSlugs` in Go (a test keeps them equal): `admin`, `api`, `app`, `assets`, `auth`, `badge`, `dashboard`, `docs`, `embed`, `feed`, `health`, `healthz`, `help`, `login`, `logout`, `maiak`, `metrics`, `public`, `readyz`, `register`, `robots`, `root`, `rss`, `settings`, `signup`, `static`, `status`, `support`, `system`, `www`. A `description` (0-500, plain text) was added to the branding fields.
- **Who builds snapshots.** The builder is Go (`statuspages.Build`), not SQL: it runs in a tenant transaction under RLS and returns the typed `Snapshot`, whose JSON keys a golden test fixes. The api rebuilds a page in the same transaction as every change (so publish, unpublish and edits are public on the renderer's next cache miss), and jobs rebuilds every published page every 30 s (`rebuild_status_pages`, advisory lock, one tenant transaction per page) after listing them through the definer `status_page_published_pages()` (`maiak_worker`). Writes therefore need no definer function; the "allow-list" guarantee comes from the typed builder, the golden test, and the renderer, which decodes the payload into the same type and re-encodes it, so a stray stored field can never be served.
- **Read function.** `status_page_snapshot(slug)` returns payload, ETag, time and password hash only for a published, live page of an active tenant whose snapshot has the page's current slug. The bootstrap creates `maiak_statuspage` (read-only transactions by default, 5 s statement timeout, connection limit 10) and grants it `EXECUTE` once the function exists; the migration grants it only when the role already exists. On an existing database the db bootstrap must run once (runbook `status-page.md`, L-292).
- **Status rules.** Component: paused or unknown is `no_data`; down is `outage`; up with failed checks below the threshold in a location (`consecutive_failures > 0`) or with a location down is `degraded`. Overall as decided, plus `no_data` ("No status data yet") when no component has data, instead of claiming "operational". Day bars: operational at 99.9 % uptime or more, degraded at 99 % or more, outage below, `no_data` without checks (L-295). Uptime is rounded to three decimals in the snapshot.
- **Incidents.** Every automatic incident of a component's monitor that is open or ended within 90 days (at most 500), newest first, titled "<public name> is unavailable"; incidents closed by a pause or a URL change count too. The public `id` is a hash of page and incident ids, never the id.
- **Components** are edited as one ordered list (`PUT /status-pages/{id}/components`): create, rename, regroup, reorder and remove in one call, at most 50. Consecutive components with the same group form one block. Monitors of any project may be used (admins see every project). A deleted monitor's component disappears from every read at once and its row is deleted by jobs.
- **Routes.** `/status/<slug>`, `/status/<slug>.json`, `/status/<slug>/feed.rss` (an item when an incident opens and one when it resolves), `/status/<slug>/badge`, `/status/<slug>/embed.js`, `POST /status/<slug>/unlock` and `/status/_assets/status.css` (cached a day, versioned). Every other path, wrong method, malformed slug, and the JSON, RSS, badge and embed of a protected page share the same byte-identical 404.
- **Headers.** The page's CSP is `default-src 'none'; style-src 'self' 'nonce-…'; img-src <logo origin>|'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`: narrower than the decision's `img-src https:` (only the logo's own origin, re-validated when rendering; the server never fetches the logo). The nonce is fresh per response, so HTML has `Cache-Control: public, max-age=30` and no ETag; JSON, RSS and embed.js have the snapshot's ETag. The page carries no script and no style attribute; bars are classes. The badge has `frame-ancestors *` and `Cross-Origin-Resource-Policy: cross-origin`.
- **Password.** The unlock cookie (`maiak_status_unlock`, 12 h, `HttpOnly`, `SameSite=Lax` since P-06, `Path=/status/<slug>`) is an expiry plus an HMAC over the slug, a digest of the password hash and the expiry, keyed with `MAIAK_STATUSPAGE_COOKIE_KEY` from the Secret `maiak-statuspage` (generated by `maiakctl secrets bootstrap`, ADR-0091, or an ExternalSecret). A new password invalidates every cookie. Checks run one at a time per replica (64 MiB argon2id), limited to 10 per client (IPv4 address or IPv6 /64) and 100 wrong passwords per page per 15 minutes with a per-client reserve (P-06); a cross-site form post is refused (Origin and Sec-Fetch-Site).
- **Limits and cache.** Page views 60 burst and 2 per second per client IP (X-Forwarded-For with `MAIAK_TRUSTED_PROXY_HOPS`); lookups cached 15 s per slug, unknown slugs too, at most 10 000 entries, one lookup per slug at a time (L-274).
- **Look.** Server-side `html/template`, every field escaped; tokens copied from the web design system into `status.css` with `light-dark()` pairs, system fonts (L-294); status shapes and words as in the app; the accent only draws the header rule and link hovers. Phones show 30 days of bars, wider screens 90.
- **Preview.** The admin's preview is `GET /status-pages/{id}/preview` (the same encoder as the public JSON, also unpublished) drawn by the web app with unsaved branding; there is no shareable preview URL of an unpublished page (L-293).
- **Review fixes (P-06).** The unlock cookie is `SameSite=Lax` (a link from a mail or chat to an unlocked page keeps working; the cookie only reads). Limits key IPv6 clients by their /64. The per-page password budget (100 per 15 minutes) counts only wrong passwords, and when it is exhausted every client keeps a reserve of 3 wrong passwords of its own on that page, so an attacker cannot lock visitors who know the password out; the per-client limit (10 attempts per 15 minutes) still applies. Limiters evict the least recently used key one at a time instead of dropping arbitrary keys. Incidents: every open incident is read, plus at most 2000 resolved ones per monitor (90 days), so one flapping component cannot hide another's outage; heartbeat bars use all of them, and the page lists the newest 100 past incidents. A freed address (delete or rename) stays reserved for its organization for 30 days (`status_page_released_slugs`, definer `status_page_slug_held(slug)` for `maiak_api`), and every refusal of an address has the same answer, "This address is not available". Pausing, resuming and deleting a monitor refresh the published pages that show it in the same transaction. Titles, descriptions, public names and group names refuse invisible format characters (Unicode Cf: bidi overrides, zero-width spaces), in the API and in the web form.
- **Chart.** `statuspage` Deployment and Service, `/status` on the HTTPRoute before the web catch-all, metrics Service, NetworkPolicy port; `statuspage.enabled` is false in `values-platform.yaml` until the db bootstrap has run once (L-292).

## Alternatives considered
- Rendering the page from the api with live queries: every visitor would hit the read models and the api's role, and a spike would hurt the dashboard.
- A static site pushed to object storage or a CDN: no infrastructure for it in `klr-platform` yet; the snapshot table keeps that option open.
- A status page per project: possible later with the same schema; organizations asked for one page that spans teams.
